# Необязательный вход через Google

Игрок может привязать Google к существующей гостевой сессии через Supabase `linkIdentity`. ID сессии остаётся прежним, поэтому комнаты, голосования и место ведущего сохраняются. На другом устройстве обычный вход через тот же Google восстанавливает тот же ID. Вернуться можно через действующий список комнат. Локальные партии и обучение хранятся на устройстве. Если Google-аккаунт уже привязан к другому игровому аккаунту, игрок может войти отдельно после подтверждения смены аккаунта.

## Подключение

1. В Google Cloud настройте экран согласия и OAuth-клиент веб-приложения для Supabase. Введите HTTPS callback, показанный на странице провайдера Google в Supabase Auth. Добавьте тестовые Google-аккаунты перед внешним тестированием.
2. В Supabase Auth включите Google и ручное связывание аккаунтов. Внесите ID и секрет Google в настройки провайдера. Секрет хранится только в Supabase. Сохраните включённый гостевой вход.
3. Добавьте в список разрешённых адресов возврата Supabase точные значения для используемых сборок, например `https://game-of-concepts.vercel.app/?auth=google`, при локальной разработке `http://127.0.0.1:5173/?auth=google`, для Android `com.xikosan.gameofconcepts://auth/callback`. Для отдельной страницы предпросмотра укажите её путь. При изменении домена проверьте также Site URL. APK открывает форму через Capacitor Browser, а приложение обменивает код возврата с помощью PKCE.
4. Добавьте `VITE_ENABLE_GOOGLE_AUTH=true` в окружение нужной веб- или Android-сборки и пересоберите её. Без этого флага интерфейс остаётся гостевым. Начните с закрытого теста на подключённом Supabase-проекте. Публичное включение сделайте после проверки браузера, APK и обработки запросов на удаление.

## Проверка перед запуском

- Создайте гостевую комнату на ПК, привяжите Google. Сверьте, что ID, место, никнейм и права ведущего сохранены.
- Войдите на другом устройстве через тот же Google. Откройте заполненную комнату через «Вернуться» с пустым полем никнейма. Сверьте руку, счёт и возможность хода. Проверьте обратный переход с Android на ПК.
- Проверьте отказ Google, уже привязанный аккаунт, отмену смены аккаунта, выход только на текущем устройстве и повторный вход. При отмене сессия гостя должна по-прежнему открывать его комнату.
- Проверьте, что гостевая и локальная игра работают с выключенным флагом, а вход и выход не удаляют локальные сохранения.
- Проверьте, что ссылка в настройках аккаунта открывает публичную страницу **Удаление аккаунта**. До публичного включения протестируйте ручную обработку запроса на тестовом аккаунте. [Требования Google Play](https://support.google.com/googleplay/android-developer/answer/13327111)

## Ручная обработка запроса на удаление

1. Найдите аккаунт по подтверждённой почте в Supabase Auth. Проверьте владение аккаунтом ответом на сообщение, отправленное на этот адрес. Свяжитесь с игроком по поводу активных партий.
2. Проверьте комнаты, содержащие ID во владельце, списке участников и игровом состоянии. Согласуйте завершение активных партий. Удаляйте нужные комнаты целиком по согласованной процедуре, чтобы не оставить ходы и голоса со ссылками на удалённого игрока. Проверьте связанные диагностические записи после обработки комнат, поскольку удаление комнаты тоже создаёт событие архива. Проверьте также технические записи, связанные с аккаунтом, и исследовательские записи, которые можно связать с ним через идентификатор партии.
3. После обработки связанных записей удалите пользователя через Supabase Auth с административным доступом. Проверьте, что обновление сессии и возврат в старые комнаты недоступны. Ранее выданный JWT может оставаться действительным до истечения срока. Сообщите игроку, какие данные удалены и какие остаются по обоснованной причине.

[Удаление пользователя в Supabase](https://supabase.com/docs/guides/auth/managing-user-data#deleting-users)
