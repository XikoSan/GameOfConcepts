# Диагностический архив партий

Это отдельный архив для разработчиков со сроком **30 дней**. База `relation_research.accepted_relations` для будущего соперника сохраняется независимо, без этой очистки.

## Что сохраняется

Начало или восстановление локальной партии; отправка хода на голосование; принятие, отказ или отмена; промежуточные голоса; пас; пересдача; предложение завершить партию, голоса и результат. Онлайн дополнительно архивируется удаление комнаты. Изменение типа связи в редакторе само по себе не создаёт архивную запись: полный выбранный набор сохраняется при отправке хода.

Каждая запись содержит снимок публичного поля, владельцев карт по номеру места, конфигурацию колоды, число оставшихся карт, принятые и предложенные связи с порядком добавления, счёт и сохранённые основания бонусов. Имена, руки, порядок колоды, UUID участников/Auth, токены, речь, IP и текст обоснований не сохраняются. Голоса хода представлены только числами «за/против/требуется», голоса завершения — позициями игроков.

Снимок хранит все принятые начисления на этот момент. Исторические объяснения остаются теми, что были рассчитаны при принятии; будущие карты не изменяют архивный расчёт. Старые сохранения без объяснений так и отмечаются отсутствующими сведениями. Локальные данные считаются сообщениями клиента, а не доказательством честного голосования.

## Хранение и доступ

- Закрытая схема `game_diagnostics`, таблица `events`. Нет публичного чтения, схема не добавляется в exposed schemas.
- Онлайн: PostgreSQL-триггер получает доверенное состояние `rooms.game_state` после серверного действия и сохраняет только разрешённые поля. Архив не связан каскадным удалением с комнатой.
- Локально: сбор включается только явным запуском/восстановлением локальной партии. Меню, неиспользуемый локальный controller в online и обучение не создают диагностические сессии. Учебный controller отдельный.
- Локальный write-only RPC `record_local_diagnostics(events)` требует гостевой авторизации. Не более 4 событий / 2,2 MB на запрос и 120 событий за минуту на гостя. Сервер повторно удаляет все поля вне белого списка. Имена или руки нельзя передать через вложенный произвольный JSON.
- Дубликат `(source, session_id, event_id)` игнорируется. Повторная отправка не обновляет срок хранения.
- Истёкшие записи сразу исключаются из служебного экспорта, `pg_cron` физически удаляет их ежечасно на 17-й минуте. Запись истекает через 30 дней с момента события (для локальных часов не позднее 30 дней с момента получения). Записи `accepted_relations` не затрагиваются.

Применить `supabase/diagnostics.sql` в существующем Supabase. Миграция транзакционная, повторное применение сохраняет архив и переустанавливает одноимённый hourly job. Ошибка онлайн-архивирования не блокирует игровое действие; PostgreSQL выдаёт warning. Ошибка локальной отправки оставляет события в очереди.

## Локальная очередь и границы

Очередь записывается на устройстве, повторяется после подключения и каждые 30 секунд, пока приложение открыто. Срок очереди 30 дней; до 240 последних событий и 10 MiB, одно событие до 1 MiB UTF-8. При переполнении удаляются старейшие записи; новейшие полные снимки сохраняют принятые связи и начисления, но часть промежуточных отказов/голосов может отсутствовать. Очищенные данные приложения восстановить нельзя. Это диагностическая помощь, не облачное сохранение игровой сессии.

React updater создаёт только чистые неизменяемые события, а storage/network выполняются в effect. Повтор StrictMode создаёт тот же event id для той же committed revision. После перезапуска устройства новый run id не конфликтует с прежними событиями; восстановление партии отмечается `resume`.

## Экспорт для разработчиков

Использовать аутентифицированный служебный инструмент проекта по конкретному коду комнаты или идентификатору сессии. Публичную админ-кнопку и service-role ключ в клиент не добавлять.

Прямой owner SQL:

```sql
select game_diagnostics.export_room('КОДКОМНАТЫ');
select game_diagnostics.export_session('local', 'IDНЕЙТРАЛЬНОЙКАРТЫ');
```

Формат: `{formatVersion:1, source, roomCode|sessionId, events:[...]}`. Записи события содержат `source, session_id, event_id, event_type, occurred_at, received_at, expires_at, room_id, room_code, client_version, server_version, snapshot`.

В snapshot: `formatVersion, scoringVersion, playerCount, currentPlayerIndex, startCardId, drawPileCount, deck, board[], semanticEdges[], scores[], redrawUsed[], logDetails[], pendingMove, pendingFinish, gameOver, endReason, consecutivePasses`. Board имеет `id, definitionId, cardName, x, y, playerId, status`. `logDetails[]` имеет номер, место игрока, понятие, прирост/общий счёт и semanticScore с frozen explanation. `client_version` заполняет локальный клиент; в онлайне фиксируется версия серверного обработчика, точная клиентская версия неизвестна.

Архив начинается после установки обновления; прежние партии задним числом не импортируются. Если данные не пришли с устройства до истечения срока, их не будет на сервере. Для текущей онлайн-комнаты можно отдельно выгрузить публичное состояние по точному коду — это ещё не архив предыдущих голосований.
